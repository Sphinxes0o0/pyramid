# TCP

## TCP概述

TCP（传输控制协议）提供面向连接的可靠字节流服务。主要特点：
- TCP将数据分割成适当的块
- 使用超时重传机制和确认
- 校验和验证数据完整性
- 重排乱序段
- 每端固定缓冲区大小
- 提供不解释内容的字节流服务

## TCP头部格式

TCP数据封装在IP数据报内。头部包括：
- 序列号（SYN和FIN消耗一个序列号）
- 标志：SYN（发起连接）、ACK（确认）、URG（紧急指针）、PSH（推送数据到应用）、RST（重置连接）、FIN（结束发送）
- 窗口大小用于流量控制（最大65535字节）
- 覆盖头部和数据的校验和
- 紧急指针（仅当URG=1时有效）

**关键限制：** TCP缺乏选择性确认——它确认收到的字节但不能确认数据流的特定部分。

## TCP连接过程

### 三次握手

1. 客户端发送SYN和初始序列号（ISN）
2. 服务器响应SYN + ACK（序列 = ISN+1）
3. 客户端发送最终ACK（序列 = ISN+1）

### 四次握手（连接终止）

由于TCP的半关闭特性：

1. 客户端发送FIN
2. 服务器响应ACK + FIN（通过背靠背组合）
3. 客户端确认ACK

## 关键概念

### MSS（最大段大小）

连接建立期间通信的最大段大小，限制每个数据包发送的数据量。

### Nagle算法

合并小数据包以减少网络开销。对于延迟敏感的应用可以禁用（TCP_NODELAY）。TCP_CORK通过缓冲数据最大化吞吐量。

### Keepalive

2小时空闲后检测空闲连接状态。检查：
- 正常响应
- 崩溃的客户端（10次探测后无响应）
- 客户端重启（收到RST）
- 不可达网络

### 路径MTU发现

使用IP头中的DF位发现路径上的最大传输单元，避免分片。

### 长肥网络（LFN）

高带宽延迟积网络面临挑战：
- 窗口缩放需要>65535字节
- 需要快速重传/恢复算法
- 时间戳选项用于准确的RTT测量
- PAWS算法防止序列号回绕

### 超时和重传

四个TCP计时器：
1. 重传计时器
2. 坚持计时器（窗口更新）
3. Keepalive计时器
4. 2MSL计时器

**RTT计算：** 使用均值和偏差：RTO = A + 4D

**拥塞控制：**
- 慢启动：cwnd从一个段开始，每个RTT翻倍
- 拥塞避免：每个ACK增加1/cwnd

**快速重传：** 由3+个重复ACK触发，随后进行快速恢复而非慢启动。

### 滑动窗口

- 无需等待每个ACK即可连续发送
- 窗口大小反映接收者可用缓冲区
- 窗口可以收缩但右边缘不能左移
- PUSH标志强制立即传递数据
- 带宽延迟积决定最佳窗口大小
