# 4.3 负载均衡部署拓扑

本节将介绍四种负载均衡部署拓扑，不同的部署拓扑决定了流量如何被分配、如何实现冗余和高可用性，进而影响系统的性能、可扩展性和容错能力。

## 4.3.1 中间代理型

第一种是中间代理型部署拓扑。如图所示，这是最常见的负载均衡部署方式，负载均衡器位于客户端与后端服务器之间，负责将请求转发至多个后端服务器。

在中间代理型拓扑中，负载均衡器可分为三类：
- 硬件设备：由 Cisco、Juniper、F5 Networks 等公司提供的硬件负载均衡设备
- 纯软件：如 Nginx、HAProxy、Envoy 和 Traefik 等开源软件负载均衡器
- 云服务：包括阿里云 SLB、AWS ELB、Azure Load Balancer、Google Cloud Cloud Load Balancing 等

**优点**：配置简便，用户只需通过 DNS 连接到负载均衡器，无需关心后端细节。

**缺点**：存在单点故障风险，负载均衡器故障会导致整个系统无法访问。

## 4.3.2 边缘代理型

边缘代理型是中间代理型拓扑的变种。典型示例是动态请求"加速"技术，Akamai 在全球部署边缘节点，具备代理功能，可执行安全检查（DDoS 防护），根据缓存策略决定返回缓存内容或转发至源服务器。

**优点**：降低延迟、提高响应速度、增强安全性。

**缺点**：某边缘节点故障仍会影响该节点服务的用户。

## 4.3.3 客户端内嵌

为解决中间代理型单点故障问题，出现了将负载均衡器以 SDK 库形式嵌入客户端的方案。这些 SDK 包括 Finagle、Eureka、Ribbon 和 Hystrix 等。

**优点**：将负载均衡功能转移至客户端，避免单点故障。

**缺点**：需要为每种编程语言实现相应 SDK，版本依赖和兼容性问题处理棘手。

## 4.3.4 边车代理型

边车代理型拓扑在微服务架构中广泛应用，发展成为"服务网格"架构模式。原理是在应用容器旁部署独立代理容器，实现负载均衡和流量管理。Envoy 和 Linkerd 等网络型边车代理已被广泛应用。

## 总结

中间代理型负载均衡器正逐步演变为功能更强大的"网关"，承担 TLS 卸载、请求限制、身份验证和复杂内容路由等职责。针对东西向流量，边车代理模式"透明"接管服务间通信治理，正逐渐成为主流选择。
